Two new papers sharpen the baseline picture for the spec's related-work section.

**History-Conditioned Spatio-Temporal Visual Token Pruning** (Wang et al., 2026-03-06) is a training-free spatio-temporal VT pruning framework for VLA-based vision-language navigation (VLN). It uses historical frame context to prune tokens that are redundant across time — the complementary axis to surf's structural prior, which prunes within a single observation using geometric structure. The design boundary is the zero-shot / first-step case: when no history exists, temporal pruning must fall back to spatial saliency; surf's structural prior is always valid. This is the missing temporal-vs-structural axis in surf's baseline space.

**ResPrune** (Li et al., 2026-03-22) adds a third mechanism to the text-conditioned VT pruning family: subspace reconstruction — keep the smallest token subset from which all remaining tokens are approximately reconstructible given the instruction embedding. This is a minimum-cover criterion, distinct from DPP diversity (Beyond Attention or Similarity), attention salience (SparseVLM+), and surf's geometry score (structural informativeness). The implication for surf: if line-density top-k patches don't span the reconstructive subspace of the full observation given the instruction, surf discards recoverable information. Whether this holds is testable.

## questions

- History-Conditioned × [[claims/structure helps]] design boundary: Wang et al.'s temporal pruning requires at least one prior frame; surf's structural prior is valid at frame 0. Is there a task context (dense clutter, instruction-ambiguous first step) where temporal history is informative but structural geometry is not? Testing first-frame-only vs. full-sequence token selection on LIBERO would isolate this boundary and clarify what surf's first-step advantage actually covers.
- ResPrune × scorer design: If line-density top-k patches fail ResPrune's reconstruction-sufficiency criterion on manipulation frames — i.e., dropped low-density patches are not reconstructible from selected patches given the instruction — surf's selector is informationally incomplete in a precise sense. Is there an empirical test (per-token reconstruction error × action success rate) that quantifies whether reconstruction insufficiency causes task failures vs. being informationally redundant?
- Dynamic Resolution Routing × surf's patch granularity: Sun et al.'s routing assigns different resolutions to different crops. Surf assigns inclusion/exclusion at uniform resolution. Are these equivalent at sufficiently fine patch granularity, or does the task-relevant structural detail live below ViT patch resolution (e.g., sub-patch edge configurations near contact surfaces)?
- MAViE × scoring feature layer: @palaciosVisualInstructionTuning2026 shows intermediate layers are optimal for vision-centric fine-tuning. MAViE uses adaptive routing per token. What is the optimal feature layer for surf's scorer input? Does the best layer for scoring (selecting) tokens match the best layer for representing selected tokens downstream, or do they decouple?
- KV Cache RD framing × visual budget: If patch selection is rate-distortion minimization over the task-relevant feature covariance, what is the correct covariance estimate — empirical covariance of instruction-conditioned ViT features on LIBERO frames? This would make k directly interpretable as an RD operating point and ground the budget selection procedure theoretically.
