## papers

### digest (auto)

**core**

- [G3Ego: Gaze-Guided Graphs for Egocentric Action Understanding](https://arxiv.org/abs/2608.20157v1) — Haralović et al. · arXiv · 2026-08-20
  Uses gaze fixations as the structural cue to identify action-relevant entities in egocentric video, then builds action scene graphs from them via a VLM. This is the direct empirical case that gaze finds what matters for action — the same claim surf's structural prior makes about line-density patches. Testable overlap: do G3Ego's gaze-selected entities on LIBERO manipulation frames match surf's top-k line-density patches? If yes, that's converging structural evidence for [[claims/structure helps]] and a concrete [[eval/gaze]] reference point.

- [Question-Guided Evidence Acquisition for Multimodal Visual Question Answering](https://arxiv.org/abs/2608.19739v1) — Popa · arXiv · 2026-08-20
  Frames document VQA as iterative, question-conditioned visual evidence acquisition rather than single-pass encode-and-answer. The question drives repeated passes over the image, each gathering additional evidence. Mechanically equivalent to surf's task-conditioned patch selection but in documents; the iterative scoring + stopping criterion is directly relevant to [[claims/iterative selection]] and the "when to stop selecting" question from open questions.md.

**adjacent**

- [Learning When to Think: Adaptive Reasoning for Test-Time Compute Allocation](https://arxiv.org/abs/2608.20256v1) — Kassenaar et al. · arXiv · 2026-08-20
  RL-trained model selects compute mode (NoThink / Short / Long) as its first output token, learning from task-performance rewards alone. The RL framing (compute allocation as a policy, verifiable task reward) is directly importable to [[claims/iterative selection]] — the same adaptive budget question surf faces but in the reasoning domain. The "first token = budget decision" trick is a lightweight way to wire the compute policy into an existing VLA without a separate scorer head.

- [DECOWAM: Decoupled Whole-Body World-Action Model for Legged Mobile Manipulation](https://arxiv.org/abs/2608.20114v1) — Ma et al. · arXiv · 2026-08-20
  Separates camera ego-motion (from locomotion) from arm motion in a whole-body world-action model via dedicated conditional interfaces, freezing a FastWAM backbone and training residual adapters. Adjacent to surf's closed-loop VLA framing: when robot base moves, visual token importance changes not because the scene changed but because the camera did — a factor surf's per-frame token scorer currently ignores. The ego-motion decoupling here is the correction surf may eventually need.

**horizon**

- [Orthogonal JEPA: Factorized Predictive States for Latent World Models](https://arxiv.org/abs/2608.20065v1) — Cui et al. · arXiv · 2026-08-20
  Extends JEPA by factorizing latent states into orthogonal subspaces for different predictable aspects of the world (e.g., geometry, color, motion). Each subspace has dedicated encoder and prediction pathway. Horizon framing for surf: if a representation can be factorized by what aspect it encodes, surf's contrastive scorer could condition specifically on the task-relevant subspace (geometry/structure) rather than the full mixed representation — a cleaner target for [[claims/structure helps]] and [[claims/language helps]] disentanglement.

## questions

- G3Ego × [[eval/gaze]]: G3Ego's gaze-guided entity detection on egocentric video is a concrete instantiation of "gaze finds action-relevant entities." If G3Ego's selected entities (from fixation density on LIBERO frames) overlap with surf's line-density patches, that's structural validation for surf's prior without needing the full contrastive scorer. Is this testable on LIBERO's available frame annotations?
- Question-Guided Evidence Acquisition × [[claims/iterative selection]]: This paper's iterative evidence loop in document VQA has an explicit stopping criterion and evidence aggregation step. Does surf's iterative token selection need a parallel aggregation mechanism (keeping previously selected patches visible while refining), or does single-pass selection with budget constraint suffice?
- Learning When to Think × [[claims/iterative selection]]: The "first token = compute mode" approach requires no architectural changes beyond output vocabulary expansion. Could surf encode "select top-k / select top-2k / select all" as VLA prefix tokens to learn a compute policy via task-performance RL? This would make [[claims/iterative selection]] trainable without a separate scorer network.
- Orthogonal JEPA × surf architecture: If geometry and texture are predictable in separate orthogonal subspaces, and surf's structural prior selects patches by geometric content, is surf implicitly projecting onto the geometry subspace before scoring? This connection may be useful for formalizing why a structural prior separates evidence quality from noise in the spec theory section.
