**SparseVLM+** (Zhang et al., TPAMI) is the most directly threatening paper from today's digest. It proposes a training-free token sparsification method that attends to *all* text tokens rather than only special query tokens — a broader text-coverage strategy for attention-based visual selection. This directly tests [[claims/language helps]]: if broadening text token coverage in a training-free method is sufficient to identify relevant visual tokens, the contrastive scorer surf is designing may only add complexity over a simpler text-attention baseline. The distinguishing question is whether surf's contrastive formulation — explicit negative contrast against language that predicts absent structure — produces qualitatively different patch selection than SparseVLM+'s broader positive-attention sweep.

**Capturing Token Tendencies** (Ma et al.) adds pressure on [[claims/structure helps]]: static structural heuristics applied at a single layer miss dynamic token importance that emerges hierarchically across MLLM layers. If surf's line-density prior is applied at the input layer and importance redistributes in later layers, the prior may select the right patches early but miss late-emerging critical tokens. The practical question is whether an input-layer structural prior still provides useful initialization for a dynamic layer-progressive policy, or whether it introduces a selection bias the model must then correct.

- [Capturing Token Tendencies for Training-Free Token Pruning in Multimodal Large Language Models](https://arxiv.org/abs/2607.28341) — Ma et al. · arXiv 2026-07-30
  Layer-progressive token importance evaluation for MLLMs: token importance evolves across layers rather than being fixed at input, so static instantaneous heuristics (applied at one layer) produce irreversible sub-optimal filtering. Baseline threat to [[claims/structure helps]]: if surf's line-density structural prior is applied at the input layer, it may commit to an importance ordering that diverges from what the MLLM assigns in later layers. Key empirical question: do surf's structurally selected patches remain among the high-importance tokens at deeper MLLM layers, or does importance substantially redistribute?

- [WIDE: Boosting Adaptive LLM Inference via Token-level Dynamic Width Pruning](https://arxiv.org/abs/2607.28418) — Hu et al. · arXiv 2026-07-30
  Token-level dynamic width pruning for LLMs: reduces the width (number of active channels) of the model per-token at inference time rather than reducing token count. For [[claims/efficiency without collapse]]: WIDE targets per-token compute cost (width) while surf targets token count — the question is whether these are orthogonal costs in VLA inference or whether reducing token count already reduces width cost proportionally. If width and token count reductions are compositional, WIDE + surf's token selection could compound efficiency gains without quality collapse.

## questions

- SparseVLM+ × [[claims/language helps]] differentiation: SparseVLM+ attends to all text tokens (positive coverage); surf's contrastive scorer contrasts against language that predicts absent structure (negative contrast). Does negative-contrast produce qualitatively different patch selection from positive-coverage, or is the difference only in implementation complexity? A co-location comparison on LIBERO frames would settle whether the two selection maps overlap substantially.
- SparseVLM+ × [[claims/structure helps]] co-location: SparseVLM+ is text-guided and training-free; surf's prior is geometry-guided. Do the two methods select the same patches on LIBERO manipulation frames? If yes, text attention and structural geometry converge on the same signal and surf's joint contribution is additive; if no, they are complementary and surf's combination is potentially the stronger claim.
- Capturing Token Tendencies × [[claims/structure helps]] layer dynamics: Ma et al. show token importance evolves across MLLM layers. Does surf's input-layer line-density prior produce a useful initialization that reduces later-layer redistribution cost, or does it introduce a selection bias the model corrects at later layers — effectively paying twice for importance estimation? A probing experiment comparing patch importance at layers 1, 8, 16, 24 for surf-selected vs. SparseVLM+-selected patches would answer this directly.
- TacWAM × [[claims/structure helps]] phase scope: TacWAM and FA-RDP (7/31) both indicate that post-contact manipulation requires non-visual signals (force, deformation) that structural geometry cannot provide. If two independent papers converge on this, should surf's evaluation explicitly scope [[claims/structure helps]] to pre-contact phases and task-goal-alignment tokens, rather than claiming full-episode patch selection? A precision claim (pre-contact structural prior, post-contact motion/force selection) is stronger than a weaker general claim.
- WIDE × [[claims/efficiency without collapse]] composition: WIDE reduces channel width per token; surf reduces token count. For a 3-7B VLA on LIBERO, what fraction of inference FLOPs is attention (quadratic in token count) vs. FFN (linear in token count, quadratic in width at fixed count)? The answer determines whether width reduction and token count reduction target overlapping or orthogonal cost components.
- Sample More, Reflect Less × [[claims/iterative selection]] equal-budget baseline: If surf's iterative selection over K rounds uses the same total compute as single-pass with all tokens, does iterative selection outperform single-pass? If it does not, the iterative selection criterion must be justified by adaptation cost reduction (fewer irrelevant tokens in later rounds) rather than refinement quality — a different claim than "iterative is better than single-pass."
